# Gouzi Landing Page Optimization

把现有页面改造成一条连续的说服路径：先匹配用户意图，再展示价值与证据，最后用低风险、高价值钩子推动行动。不要把视觉翻新当成转化优化；每项改动都要对应用户阻力、AIDA 阶段和可观测指标。

## 品牌与组件不变量

- **Logo 不重绘**：优先直接复用原站或现有代码中的 logo 资源、组件和 class，保留原始比例、alt、加载方式和响应式行为。只有原资源不可用时，才提供明确的 fallback；不要用文字、CSS 图形或 AI 图片替代原 logo。
- **按钮风格保持一致**：沿用原站/现有页面的按钮 class、设计 token、颜色、圆角、字重、图标位置以及 hover、focus、disabled 状态。主 CTA 可以改文案和位置，但不能因为重排页面而引入另一套按钮视觉系统。
- **页面允许重新设计**：布局、区块顺序、信息层级、首屏构图、背景和内容表达可以为 AIDA、钩子和转化目标重新设计；品牌 logo 与按钮组件仍视为固定锚点。
- **先识别再改造**：有原始 HTML/CSS 或 URL 时，先记录 logo 与按钮的真实来源和样式，再决定哪些页面层级需要重排。不要把“保持品牌一致”误解为复制整页布局。

涉及视觉或前端实现时，额外读取 [references/visual-brand-and-buttons.md](references/visual-brand-and-buttons.md)，并在交付前检查品牌资源引用和按钮状态。

## 加载规则库

每次审计、重排或改写页面前，读取 [references/laws-and-rules.md](references/laws-and-rules.md)。用其中的完整规则检查页面，不要只套 AIDA 标题。

需要重写文案、选择叙事顺序、生成标题/钩子或构建案例时，再读取 [references/copywriting-frameworks.md](references/copywriting-frameworks.md)。以 AIDA 作为默认全页主干，只选择一个最适合当前任务的主框架，必要时把其他框架用于局部区块；不要把所有框架叠加到同一页面。

## 工作流

### 1. 建立转化契约

先确认或从材料中推断：

- 目标受众及其采购/购买场景。
- 流量来源、广告承诺、搜索意图或进入页面前的上下文。
- 产品、核心价值、可信证据和不能虚构的事实边界。
- 唯一的主要转化动作，以及必要的次要动作。
- 当前基线：跳出/参与率、滚动深度、CTA 点击率、表单启动率、表单完成率、询盘或购买转化率、合格线索率。

缺失信息时先审计可见页面并明确标注假设。只有当不同答案会实质改变页面策略时才提问。不要编造案例、数字、认证、客户、稀缺性或交付承诺。

### 2. 记录当前体验

同时检查桌面端和移动端。记录首屏内容、区块顺序、主要与次要 CTA、选项数量、表单字段、联系方式、信任证据、文字密度和交互阻力。

获取 URL 时实际打开页面并截取关键状态；获取代码时同时检查页面实现和响应式行为；只有截图时说明无法验证的交互、性能和提交链路。

把问题写成“证据 -> 违反的规则 -> 用户阻力 -> 指标风险”，避免只给审美意见。

### 3. 映射并重建 AIDA 递进

按以下顺序重排信息：

1. **Attention**：用高相关、真实且清晰的主视觉表明身份；让标题呼应广告/搜索意图；给出低压力、可立即执行且写明收益的 CTA。
2. **Interest**：先给最重要的价值与痛点答案；用 3–4 个代表性产品、场景或案例区块展示能力；用数据化案例和质量、交期、售后承诺降低疑虑。
3. **Desire**：把特性翻译成用户结果；展示工艺、性能、应用细节或沉浸式体验；用工厂、认证、流程、实拍、客户结果等可验证证据建立安全感。
4. **Action**：找出目标用户很想要、竞争者通常不给或难以提供的“稀缺价值”；把它包装成低风险钩子，并用清晰 CTA、精简表单和显眼联系方式完成转化。

允许在关键证据簇后重复同一个主 CTA，但保持同一承诺、同一动作和清晰层级。不要在用户尚未理解价值或建立信任前突然要求高承诺行动。

### 4. 设计钩子

按“目标用户强烈想要 + 行业中难获得 + 本方确实能交付 + 获取成本/风险低”筛选钩子。优先提供能推进决策的资产或服务，例如方案、样品、咨询、案例集、选型建议或报价，而不是笼统的“联系我们”。

为每个候选钩子写清：受众、具体价值、交付形式、获得条件、可信依据和 CTA 文案。选择与流量意图最一致的一个作为主钩子；其余降级或移除，避免选择竞争。

用 4U 检查标题与钩子：是否独特、对用户有用、足够具体、存在真实的行动时机。没有可验证的截止时间、库存、名额或业务窗口时，不制造紧迫感。

### 5. 降低阅读与操作阻力

应用规则库中的单栏聚焦、希克定律、分类/分页、重点推荐、费茨定律、CTA 对比、表单精简、联系方式显著化和文字排版规则。

默认让核心说服链保持单栏、连续且可扫描。列表型集合内容超过材料建议的 5–9 个选项时，再使用分类、筛选、分页或重点推荐；不要用分页打断核心 AIDA 流程。

### 6. 输出改版方案

至少交付：

- 一句话转化诊断和当前 AIDA 断点。
- 按影响排序的问题清单，每项包含页面证据、适用规则、指标风险和具体修复。
- 新的区块顺序，标注每个区块的 AIDA 角色、用户问题、证据和 CTA。
- 首屏标题、支持文案、主 CTA 与 2–3 个钩子候选；明确推荐项。
- 桌面与移动端布局说明，包括选择数量、表单字段和联系方式位置。
- 测试计划：假设、变量、主要指标、护栏指标及胜负判断；没有数据时不要承诺提升百分比。

优先级使用：

- **P0**：提交失败、CTA 不可用、移动端遮挡等直接阻断转化的问题。
- **P1**：意图错配、首屏身份不明、价值不清、信任证据缺失、主 CTA 或钩子无效。
- **P2**：选项过多、表单过长、CTA 难点、联系方式不显眼、阅读密度过高。
- **P3**：不影响理解和行动的视觉润色。

### 7. 实施与验证

用户要求修改代码或设计时，直接实施高优先级改动并保持现有品牌与技术栈。验证所有 CTA、表单、联系方式、下载和响应式状态，确保文案不溢出、控件不重叠、移动端触控目标易点。

把阶段与指标对应起来：

- Attention：跳出/参与率、首屏 CTA 点击率。
- Interest：25%/50% 滚动到达率、有效停留、案例区块到达率。
- Desire：证据/详情模块互动、证据后 CTA 点击率。
- Action：CTA 点击、表单启动、表单完成、询盘/购买转化率。
- 业务护栏：合格线索率、退款/取消率、每条合格线索成本。

优先做单变量或少变量实验。保留原版本、事件口径、流量来源和设备分层，避免把流量质量变化误判为页面效果。

## 质量边界

- 区分材料事实、页面可见证据、合理推断和待验证假设。
- 把 5–9 个选项视为材料中的经验规则，不当作所有场景的硬性上限。
- 不以深色、大图、动画或更大按钮本身等同于转化提升；先验证意图、价值、证据和行动链。
- 不使用虚假倒计时、虚假库存、虚假评价或无法履约的免费承诺。
- 匹配用户使用的语言输出；页面面向其他市场时，保持目标市场文案自然、具体且以收益为导向。
