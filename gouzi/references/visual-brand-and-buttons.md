# 品牌与按钮一致性规则

这份规则用于页面重排或 CSS 改版。它约束品牌识别与核心操作组件，不限制页面布局创新。

## 1. Logo 规则

- 优先从原站 HTML、CSS、设计稿或现有组件中找到真实 logo URL、文件路径或组件引用。
- 直接复用原 logo 资源；不要重新绘制字母标志、生成替代图片或用纯文字模拟品牌标识。
- 保留原 logo 的宽高比、清晰度、透明背景、alt 文本和加载优先级。
- 深色/浅色背景不匹配时，先寻找原站提供的对应变体；只能在没有变体时使用不改变轮廓的 CSS 显示适配，并记录这是显示适配而非新 logo。
- 资源加载失败时提供可识别的文本 fallback，但不要让 fallback 成为默认视觉。

## 2. 按钮与 CTA 规则

- 检查原页面已有的按钮 class、组件、颜色 token、字重、圆角、内边距、图标和状态样式，并优先复用。
- 重排页面时可改变 CTA 的文案、顺序和位置，但主次层级必须清楚：同一阶段只保留一个主 CTA，其余动作降级为次要链接或辅助按钮。
- 保持 hover、focus-visible、disabled、loading 和移动端触控尺寸；不能只复用静态颜色而丢失交互状态。
- CTA 文案继续遵循收益明确、低压力、与钩子一致的规则，例如“获取配置与报价”，不要退化成无信息量的“提交”。
- 新增按钮时，复制现有组件的调用方式和 token；不得因为页面重新设计而引入无关的渐变、描边、阴影或另一套圆角体系。

## 3. 页面可变范围

允许重新设计以下内容：首屏双栏或单栏构图、区块顺序、AIDA 递进、信息密度、背景分区、卡片布局、证据呈现、表单位置和响应式栅格。

不应随意改变以下内容：logo 资产及识别轮廓、按钮组件语义、主 CTA 的可识别性、键盘焦点可见性和触控可用性。

## 4. 交付检查

- 检查页面是否仍引用原 logo 资源或原 logo 组件，而不是新绘制的替代物。
- 检查所有主 CTA 是否使用统一 class/token，并在桌面和移动端保持一致的状态与触控尺寸。
- 检查页面新视觉是否服务于 AIDA 和阅读路径，而不是因为“看起来不同”而改变品牌组件。
- 在审计中区分“品牌组件一致性问题”和“布局/转化路径问题”，分别给出修复与指标风险。
